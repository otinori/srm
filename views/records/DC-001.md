# [DC-001] 実装言語にC# (.NET 8) を採用、C++を却下

## Context

SRMのコアを実装する言語を選定する必要があった。
Win32 API（AppContainer SID生成・ACL設定・WFPフィルタ登録）を直接呼び出す必要があり、
Windows固有のAPIへのアクセスが必須要件。


## Decision

実装言語としてC# (.NET 8) を採用する。Win32 APIはP/Invokeで呼び出す。
.NET 8はWindows 10以降に標準搭載されており、ランタイム依存は実用上問題ない。


## Rationale

メモリ安全性・開発速度・テスト容易性の観点からC++より優位。
P/InvokeによりWin32 APIへの直接アクセスも可能で、機能上の制約はない。


## Implications

- .NET 8のSelf-Contained publishでランタイム依存なしの単一exeを配布できる
- P/Invoke定義のメンテナンスが必要（Win32 APIのシグネチャ管理）
- AOTコンパイル（NativeAOT）も将来の選択肢として残る

## Rejected Alternatives

### C++ (alt-cpp)

メモリ安全性の確保が困難でバグのリスクが高い。開発速度が遅く、
テストフレームワークも貧弱。Win32 APIアクセスは可能だが、
C#のP/Invokeで同等の機能を安全に実現できるため採用しない。


### Rust (alt-rust)

メモリ安全性はRustが最も優れるが、Windows固有APIとのFFIが煩雑で
学習コストが高い。チームのC#知識を活かせないため採用しない。


## Review Triggers

- Windows以外のプラットフォームへの対応が必要になった場合
