# [DC-007] CLIコマンドパーサーにSystem.CommandLineを採用

## Context

Srm.Cli は `srm run|stop|list|logs|validate` のサブコマンド・オプション・引数を
パースする必要がある。.NET 8の標準ライブラリにはCLIパーサーが含まれないため、
外部ライブラリまたは自前実装を選定する必要があった。


## Decision

System.CommandLine（2.0.0-beta4）を採用する。
各サブコマンドを `Command` として定義し、`RootCommand` に追加してパースする。


## Rationale

Microsoft公式のCLIパーサーであり、.NETエコシステムでの採用実績が豊富。
サブコマンド・オプション・引数の宣言的な定義、自動ヘルプ生成、補完候補生成を
標準でサポートしており、自前実装よりも保守性・拡張性に優れる。


## Implications

- System.CommandLineはbeta版（2.0.0-beta4）——v0.1完成後の安定版リリースを確認し、必要なら更新する
- 各コマンドの実装は `Commands/` ディレクトリにサブコマンドごとに分離する

## Rejected Alternatives

### 自前のargs[]パーサー (alt-handwritten-parser)

サブコマンドが5つ（run/stop/list/logs/validate）あり、それぞれ異なる
オプション・引数を持つため、自前実装はヘルプ生成・エラーメッセージ・
型変換のコードが肥大化する。System.CommandLineが標準で解決する範囲を
自前で再実装するコストに見合わない。


### CommandLineParser（NuGetパッケージ） (alt-commandlineparser)

サブコマンド対応は可能だが設計がやや古く、System.CommandLineほど
.NET 8世代のAPI（ホストビルダー統合等）との親和性が高くない。
Microsoft公式でメンテナンスされているSystem.CommandLineを優先した。
